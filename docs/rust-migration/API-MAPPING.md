# API mapping: TypeScript to Rust to the JavaScript bridge

Every public name of the TypeScript reference (the merged #39, #42, and #44 on `main` at `452f782`; `src/index.ts`), where it lives in Rust, what the bridge exports, and what prior art exists. Use it as the checklist for M3 to M5 (Rust) and M6 (bridge): a group is **done** when its Rust is corpus-green and its bridge export passes the reused TypeScript tests. **Every group starts as not started here:** `undertone-pattern` and `undertone-engine` are built from the ground up in this repository (D-05).

**Prior art** describes what the lab's crates (`undertone-mini`, `undertone-dsp`) already do for a group, read from their code on 2026-11-18 (the lab's `main` at `26bbb05`). It is a hint about effort and design, never a dependency and never an oracle (the corpus recorded from the TypeScript is the only oracle):

- **Covered:** the lab has the behaviour, checked against fixtures recorded from the TypeScript.
- **Partial:** the mechanism exists but not the public call, or a 0.4.0 part is missing.
- **None:** nothing in the lab.

## The rules

1. **The bridge keeps the JavaScript names.** Every name exported from `src/index.ts` at the reference SHA is exported by `@liminal-hq/undertone` with the same name, signature, and behaviour, except the breaks listed at the end and accepted in D-06. The API report (RF-06) checks it.
2. **The Rust API is idiomatic Rust,** not a transliteration: snake_case, `Result` errors, no global state (tempo on a `Transport`, samples in a `Samples` registry, multichannel in the engine's configuration), builders with typed options structs. The bridge keeps the JavaScript globals by holding one default `Transport` and one default `Samples`.
3. **One table drives the controls.** `crates/undertone-pattern/src/controls.rs` lists every control once (JavaScript name, Rust name, `VoiceParams` field, scalar-only or patternable). The Rust methods, the WASM exports, the bridge's methods, and the name-map test are generated from or checked against it.
4. **`VoiceParams` field names are frozen** in their JSON form: the Rust struct is snake_case with `#[serde(rename_all = "camelCase")]`, and a test checks the serde names against `conformance/api/voice-params.json` (the field list read from `src/types.ts`).

## The handle and closure story

- **Patterns are handles.** A bridge `Pattern` holds a `u32` handle to a Rust tree. Every method returns a new wrapper, as every TypeScript method returns a new `Pattern`, so immutability and object identity behave as today. Building costs one node and never queries.
- **Freeing (the planner's position):** pattern handles are freed by the garbage collector (`wasm-bindgen`'s `weak-refs`, `FinalizationRegistry`); the garbage collector is the default and is correct, but it runs late (R2: with an idle page, tens of thousands of dead handles lingered in Node, Deno, and Chromium, and most of a million in Firefox, because the collector cannot see WebAssembly memory). Patterns therefore also get an opt-in `free()` and `[Symbol.dispose]()` (an addition, not a break), documented for loops that build many patterns. Engines, players, transports, and loop handles keep an explicit `free()` (loop handles keep `stop()` too). See [R2](results/R2.md).
- **`every(n, fn)` and `jux(fn)`** call the JavaScript function **once**, at construction, with a wrapper of the receiver (as `pattern.ts` does), receive a wrapper back, and pass both handles to Rust, which builds an `Every` or `Jux` node. No JavaScript runs during queries.
- **`fmap(fn)`, `new Pattern(query)`, and `signal(fn)`** with a JavaScript function become a `Foreign` leaf: Rust calls an imported function with the leaf's id and the span; the bridge returns haps as a compact buffer (fractions as `f64` pairs, values as ids into an interning table, so an object crosses once). A pattern with a foreign leaf runs only on the thread that made it; the worklet backend refuses it with a diagnostic.
- **Signals are built-in nodes, not closures** (the planner's position), so a tree with `sine.range(200, 800)` can be hashed, printed, serialised, and queried in a worker or a worklet.
- **`.query`** stays a public property on the bridge's `Pattern`: a function that calls into WebAssembly and returns `Hap` objects with JavaScript `Fraction`s (a copy per hap).
- **Data** (`VoiceParams`, `ScoreEvent`, `RenderOptions`, `PlayOptions`, and the other options bags) crosses as plain JavaScript objects through `serde-wasm-bindgen`, with declarations from `ts-rs` (D-11).

**Status (RF-20, step 1: the renderer):** `undertone_engine::render_graph::RenderGraph` is a `Graph` implementation that renders what the engine books, so an `Engine<RenderGraph>` makes samples with no Web Audio. `RenderGraph::new(sample_rate, channels, length_frames)` (and `set_length_frames`, because a booking learns the piece's length as it goes) is the constructor; `render_block(&mut [&mut [f32]]) -> usize` fills one slice per channel in any block size (the graph runs in fixed 128-frame quanta, `RENDER_QUANTUM`, so 1, 7, 128, and all-at-once blocks give identical samples), `render_all() -> Vec<Vec<f32>>` renders the rest, and `frames_rendered`, `length_frames`, and `channels` report progress. `Graph::current_time` is the start of the next quantum to render, and bookings made between blocks take effect from the next whole quantum. It renders every node the trait names: oscillators (the four types and periodic waves as band-limited tables), buffer sources, gain, biquad filters of every type, delays (feedback cycles through a delay get the specification's one-quantum minimum), the convolver (partitioned FFT, the specification's normalisation, one, two, or four channel responses), the stereo panner (equal power), the channel merger, the wave shaper (curve and 2x or 4x oversampling), the dynamics compressor, and a destination of one to eight channels with Web Audio's speaker and discrete up-mix and down-mix rules, with parameter automation per frame (set, both ramps, `setTarget`, cancel, and connected signals added). Maths goes through `math.rs`. The known differences from a browser are in the module documentation and in `conformance/README.md` ("Known differences by design"). The pattern-to-score step, `RenderOptions`, `render_to_buffer`, and the WAV encoder (RF-20 steps 2 to 4) are not part of this step, and layer 4 has no browser references yet, so renders are checked only by unit tests of each node against the specification's formulas and, for the corpus, for finite output and a broad peak bound (`tests/render_corpus.rs` renders every layer 3 score and prints its peak and RMS; it does not compare against any reference). The Graph has no `detune` or `gain` parameter on oscillators and filters (the engine does not use them), so none is rendered. Nothing was listened to.

**Status (RF-21, samples):** row 19 is done. `undertone_engine::samples::Samples` is the registry as a value (no global; the bridge holds one default and clones it into engines, a clone shares the PCM): `register_sample(name, SampleData { sample_rate, channels: Vec<Vec<f32>> }, base_note: Option<Pitch>)`, `register_samples(iter of (String, SampleSource { data, base_note }))` (stops at the first failure, as the loop does), `register_pending_sample(name, base_note)` (the reference's `registerSample(name, url)`: registered, not yet available), `load_samples(iter of (String, SampleData))` (the host-driven `loadSamples`: the bridge decodes with `decodeAudioData` and hands the channels over; every name must be registered or nothing changes), `get_sample_buffer`, `get_sample_base_note`, `is_sample_registered` (each with an optional bank), `resolve_registered_key`, and `clear_samples`. The engine owns a registry (`Engine::samples`, `samples_mut`); `RenderPlan::book_pattern_with_samples` renders a pattern with one. A sample voice books a buffer source with `playbackRate` set at the voice start to `frequency(pitch) / frequency(base note)` (1 without a pitch; `c4` when no base note was given), never loops, and ignores the pitch curve and FM; an unregistered name is skipped with a once-per-key `Warning` (key `sample:<name>`, forgotten by `clear_samples`), and a pending one is skipped silently. `Engine::is_voice_skipped` is `&self` and does not warn (the reference's room-size look-ahead does through the same lookup; the voice's own booking warns).
