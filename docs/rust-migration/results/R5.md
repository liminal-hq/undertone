# R5: the TypeScript suite against the bridge

## Verdict

**Pass with conditions.** The suite is classified (`conformance/test-classes.json`: 813 tests in 31 files), and the public-API tests in the areas a real binding covers pass at 90.6% (174 of 192), each failure caused. The R3 skeleton alone covers no area the suite calls (2 of 725 public tests pass, both false passes), so the pass is measured on a thin Rust binding of R1's pattern core that this spike added. The conditions:

- **The covered area is small and named.** It is the pattern algebra, mini-notation, signals, pitch parsing, the `note`/`sound`/`s`/`n` constructors with four controls, and the property tests: seven files, 192 of the 725 public tests. The other 532 public tests fail because nothing is bound there (the engine, effects, rendering, samples, scheduler, WAV, and the other 56 controls), and are not counted against the 90%. The margin is thin (90.6%, and 90.3% if the 7 `Fraction` tests are left out; see below).
- **Two design faults were found and fixed in the spike, and two gaps need a decision.** An exported struct passed inside a JavaScript array is moved out and its JavaScript object nulled (the R2 shape of `seq(...pats)` would break every reused pattern); `new Pattern(query, sample)` lost its sampler. The gaps: 306 public tests depend on a test hook (`resetWarnings`, and in 4 `seedContext`) that `src/index.ts` does not export, and 93 use `playVoice`/`playVoices`, which it does not export either (the two overlap in 17). Under "What it changes".
- **RF-27 is not "change the import" for most files.** 330 public tests alias, 395 need a named translation, 52 internal tests need a Rust test each, 21 run on the Web Audio backend, and 15 stay TypeScript.

### Findings from running the suite on a Rust-backed `Pattern`

- **An exported struct inside a JavaScript array is moved out of JavaScript (design fault, fixed in the spike).** The first binding passed handles to `seq`, `cat`, `stack`, `timecat`, and `arrange` as an array. wasm-bindgen's `try_from_js_value` takes ownership, so after `seq(a, b)` the JavaScript objects for `a` and `b` held a null pointer and any later use failed (`null pointer passed to rust`; it killed `pattern.test.ts` at load). R2's `every`/`jux` took one handle by reference and did not hit it. The fix is a `List` object built with `push(weight, &Handle)`, which borrows. **RF-24 must define every variadic or list-taking entry (`seq`, `cat`, `stack`, `timecat`, `arrange`, `choose`) this way, never as an array of handles.**
- **`new Pattern(query, sample)` needs its sampler carried (fixed in the spike).** R1's `CustomQuery` has `sample` and `has_sampler`, but R2's host function left them out, so a derived pattern (`clock.fast(2)`) lost the sampler and about 20 tests failed (`sampler and query agree`, `rev on a signal`, `euclid on a signal`). With the sampler wired through, all pass. RF-25 step 4 must pass both functions.
- **Values from JavaScript.** `Pattern<Value>` holds numbers, strings, booleans, and plain objects of those. The pattern, mini, and signal tests use only those, so no test failed for "this JavaScript value cannot be held" (0 failures with that message). Arrays, `undefined` as a value, class instances, and functions do raise a clear error in the spike; the reference allows them in `pure(x)`. The suite does not use them, but the user API does (`pure([1, 2])`): that is a D-06 question for RF-25, not a finding of this run.
- **The reference's properties ran against the Rust-backed Pattern unchanged** (7 of 7), through `loadReference` resolved to the binding.

## What it changes

- **RF-27 (what to do per file)** is the "Per file" table above. The accepted change to the plan's wording: steps (1) says "changing only the import and the fake context's import", which is true of 386 public tests (alias). For the other 339 a named translation is needed: **a testing entry point** (see below), and `playVoice`/`playVoices` calls become `playParams(ctx, [patch], { when })` (the engine tests pass a resolved `VoiceParams`, so the translation also passes the patch that produced it). Internal tests each need a named Rust test: the JSON's `rf27: "replace"` rows are the list (52, with the subject function in `note`); the column for the Rust test's name is for RF-27 to fill.
- **A testing entry for the package (a decision for the person, recommendation below).** 306 public tests depend on `resetWarnings` (the once-only warning set is process state; most call it from a `beforeEach`), 4 on `seedContext` (a per-context seed for noise and impulse responses), and 93 on `playVoice`/`playVoices`. None is in `src/index.ts`, and the API report (RF-06) lists only `index`. **Recommendation:** a second entry, `@liminal-hq/undertone/testing`, exporting `resetWarnings` and `seedContext`, documented as not part of the API and excluded from the API report; RF-27 imports it from the tests. Without it, RF-27 either reaches into the package's internals (fragile) or drops about 300 tests from the 100%.
- **Bridge design (RF-24 and RF-25):** lists are built with borrowing calls, never as arrays of handles; the custom leaf takes a query and a sampler; JavaScript-side validation messages (`add() needs a number...`) stay in the TypeScript wrapper and RF-25 step 6 must test them against the corpus; `toThrow()` without a message must not be trusted before the export exists.
- **Plan files not changed.** The M6 RF-27 wording and the API-MAPPING text are not edited here: the findings are for `results/DESIGN-ADJUSTMENTS.md` at the M2 exit (the testing entry; the suite is 813 tests, not 753).
- **A kept artefact:** `conformance/test-classes.json` and `bun run test-classes:check` stay in the stack (the check is a repository command; the orchestrator adds it to CI). Everything under `spikes/r5-suite/` is throwaway except `classify.mjs` and `report.mjs`, which RF-27 may reuse.

## What was not verified

- **Nothing was listened to.** Every test in this suite asserts patterns, haps, or the call log of a hand-written fake `AudioContext`; none measures perceived sound, and none was run in a browser or an `AudioContext`.
- **The binding is not the bridge.** It covers the pattern core only; there is no engine, scheduler, effects, rendering, or samples binding, so no graph, render, or timing test ran against Rust. The 90% is the pass rate of the covered area and says nothing about the other 532 public tests.
- **The 725 public tests were classified by rule, not one by one.** A public test that pins internal structure through the public API, and a P1 test that is really about a context quirk, are not found by the rules.
- **`Fraction` stayed JavaScript**, so the 7 `fraction.test.ts` passes do not test Rust (see the table). The numbers cross as `f64` numerator and denominator pairs, which loses exactness above 2^53; no test reaches it, but the corpus's layer 1 cases with large times were not rerun here.
- **WebKit, Deno, and the browsers were not used**; the suite ran in Node 22 only (R3 covers loading in the others).
- **The Web Audio class was not run** against a Web Audio backend (none exists yet); it only has its list.

## Addendum: a mixed test found in review

A local review of the pull request found that `shaped waves as sound types > are recognised sound types and not read as sample names` had been classed internal (rule I1) because it asserts on `isSoundType`, which `src/index.ts` does not export, although it also calls the public `s('abssine').play(...)` and checks that an oscillator with a periodic wave is created. Replacing it with a Rust unit test alone would have dropped the end-to-end check that the bridge books the right Web Audio graph. It is now public, rule **M1** (mixed), translate: RF-27 keeps the playback assertion against the bridge and ports the `isSoundType` assertion to a Rust unit test. The classifier now applies M1 automatically (a test with a private symbol whose body also plays, renders, queries, or reads the fake context's nodes), re-running it changed only this one test of the 67 left internal, so no other test is affected. Counts: public 725, internal 67, Web Audio 21.
