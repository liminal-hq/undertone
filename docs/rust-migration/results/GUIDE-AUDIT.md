# Guide audit: exports against the documentation

Audited on the 0.4.0 reference at `40b2cbf` (the merged TypeScript, before the edits listed below). Every export of `src/index.ts` is listed once, from the generated report `conformance/api/undertone.api.md`, and checked against `docs/guide/*.md`, `docs/recipes.md`, and `README.md`.

## Headline numbers

- **Exports:** 116 (70 values: functions, constants, and classes; 46 types and interfaces).
- **Documented somewhere (guide, recipes, or README) by name:** 75. **Not documented by name:** 41, of which 41 are types and 0 are values.
- **With a `ts standalone` example:** 45. **With a plain `ts` fragment only:** 0. **With neither:** 71.
- **Guide edits made in this change:** 6 (listed below), covering 20 exports that were previously not documented or had no runnable example.

## Method

A page counts as documenting an export when it names it: a call `name(` for functions, an import of it, or the bare identifier for types and constants. A `ts standalone` example is a fenced block with that info string (the blocks `docSnippets.test.ts` runs) that mentions the export. The check is mechanical, so a type that is described by its fields but never named is reported as not documented, with a note saying where its fields are covered. Methods of `Pattern` (about about 80 chainable controls and transforms) are out of scope for this table, which follows the export list; `README.md`'s API tables cover them and a method-level audit belongs to M2 and M5.

## Guide edits made

Each edit is a short section or paragraph with a `ts standalone` block, run by `bun run test`.

1. `docs/guide/getting-started.md`: new section "Looking inside a pattern" for `Fraction`, `Hap`, `TimeSpan`, and `hasOnset` (the types were named nowhere; `hasOnset` was undocumented).
2. `docs/guide/melody-and-harmony.md`: new section "Note names, MIDI numbers, and frequencies" for `noteToMidi`, `noteToFrequency`, and `midiToFrequency`.
3. `docs/guide/samples.md`: new bullet "Checking the registry" for `isSampleRegistered`, `getSampleBaseNote`, `getSampleBuffer`, and `clearSamples`.
4. `docs/guide/stereo-and-surround.md`: new subsection "The gains behind a placement" for `surroundGains`, `foldToStereo`, `CHANNEL_ORDER`, and `MAX_CHANNELS`.
5. `docs/guide/effects.md`: new paragraph "Reaching the buses directly" for `getOrbitBus`, `OrbitBus`, and `buildImpulseResponse` (`resolveParams` remains README-only, see below).
6. `docs/guide/fm-synthesis.md`: new paragraph for `SHAPED_WAVE_TYPES` and `isShapedWave`.

## Larger gaps, for later milestones

- **Option and handle types are never named in prose** (41 types). Their fields are described where they are used, but a reader cannot look up `LoopOptions`, `PlayOptions`, `RenderOptions`, `ScoreDefinition`, or `MasterBusOptions` by name. The M6 bridge docs and the M5 Rust guide should add an options reference page; generated API docs (`docs/api/`) already cover them.
- **The structural Web Audio types** (`AudioContextLike` and the `*Like` family) are implementation details with no prose at all. M6 should document them as the contract a bridge context must satisfy.
- **`resolveParams`** is described only in the README API table; the guide never shows turning a control patch into voice parameters. It is the seam the Rust engine port (M3) tests against, so document it then.
- **Values with no runnable example:** `brand`, `brandBy`, `choose`, `cosine`, `cosine2`, `createMonoFold`, `irand`, `isaw`, `isaw2`, `mini`, `Pattern`, `pure`, `rand2`, `renderToBuffer`, `resetTempo`, `resolveParams`, `saw2`, `seq`, `setcpm`, `signal`, `silence`, `square2`, `timecat`, `tri`, `tri2` are documented but show no `ts standalone` block (or, for some, no code at all). M2 and M3 need a runnable example per function, so add them as each area is ported.
- **Method-level audit of `Pattern`:** not done here.
