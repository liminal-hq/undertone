# Risks

Read this at the start of each milestone and add a row when a new risk appears. Decisions are in [DECISIONS.md](DECISIONS.md).

| Risk                                                                                                                                                        | Where it bites                                     | Likelihood      | Mitigation                                                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **The reference is wrong somewhere** (a bug in the merged TypeScript becomes a corpus case)                                                                 | M3, M4                                             | Medium          | A case the reference gets wrong is raised with the person, not "fixed" silently; the property tests also run against the reference to catch its own violations                                                                |
| **Everything is built from scratch** (nothing is inherited, so the first pattern and engine code is all new work, and the lab's prior art may tempt a copy) | M2, M3, M4                                         | Medium          | The corpus recorded from `452f782` is the only oracle; the lab's crates are read for ideas only and never copied or depended on; each package lands with its corpus cases; R1 de-risks the pattern tree first                 |
| **JavaScript semantics** (doubles, `Math.round` ties toward +∞, number formatting for seed keys, UTF-16 positions, exact error text)                        | Corpus failures                                    | High, but known | A `js` module of JavaScript number and string rules is written in RF-07 and RF-13; error text and positions are corpus cases                                                                                                  |
| **Signals as nodes do not cover everything** (`signal(fn)`, mixed continuous and discrete compositions)                                                     | RF-16                                              | Low to medium   | R1 first; `signal(fn)` is a foreign or custom leaf by design                                                                                                                                                                  |
| **Loading before first use** under some bundler targets                                                                                                     | RF-25, users                                       | Medium          | R3; documented config; `init()` fallback (D-17)                                                                                                                                                                               |
| **Bundle size**                                                                                                                                             | Load time for web users                            | Medium          | R4; budgets as failing checks; optional sub-modules                                                                                                                                                                           |
| **The Web Audio replay is not byte-identical** (ordering, default fields, warnings)                                                                         | RF-26, the reused tests                            | Medium          | R3 tests five graphs early; the recorded-graph tests are the oracle                                                                                                                                                           |
| **Worklet DSP on weak devices**                                                                                                                             | RF-29                                              | Medium          | Opt-in; Web Audio stays the default; SIMD; documented numbers                                                                                                                                                                 |
| **Maths across platforms** (the C library against `libm`, macOS and Windows)                                                                                | Fixtures, renders                                  | Medium          | R9; `libm` everywhere if needed; tolerances in layer 4                                                                                                                                                                        |
| **The live site shows 0.4.0 features npm does not have**                                                                                                    | Until RF-33                                        | Certain         | Accept (D-01 is done), or add the optional homepage note "the features marked 0.4.0 arrive in the next release" in a small `docs:` pull request                                                                               |
| **CI cost and contributor friction** (a Rust toolchain for a TypeScript contributor)                                                                        | Every pull request                                 | Medium          | RF-04 measures; path filters and a nightly job if slow                                                                                                                                                                        |
| **The shared CI image moves** (the pinned `ci-rust` digest ages, or the image lacks a tool)                                                                 | Every Rust job                                     | Low             | Public and pinned by digest, so it never changes under CI; bump the pin from `liminal-hq/.github`'s recommended pins on purpose; the image has no `wasm32` target (the wasm job adds it) and no Node                          |
| **Scope creep** (new features while porting)                                                                                                                | Every milestone                                    | Medium          | `main` takes no new features until RF-33 except what the plan lists; ideas go to issues                                                                                                                                       |
| **The person's time** (reviews, listening, device checks, go-ahead for each stack merge)                                                                    | Stack merges, RF-29, RF-33                         | High            | Stack merges and stop points batched into single messages; agents do the porting and the corpus; the person reviews, listens, and says go                                                                                     |
| **Stack mechanics** (a `gh stack` that grows past six pull requests, an out-of-order push, a rebase that rewrites reviewed commits)                         | Every milestone                                    | Medium          | Three to six pull requests per stack, each green alone; merge only from the top with `--merge`; fix a lower pull request with a new commit and let the stack restack; the orchestrator checks `gh stack view` after each push |
| **Agent output quality** (Sonnet agents write the code)                                                                                                     | Every work package                                 | Medium          | The orchestrator writes each brief (acceptance, files, conventions, clean-room rule, the corpus case required), reviews every diff and gate result itself, and requests fixes before a pull request joins the stack           |
| **Disk and memory** (Rust build output, WASM experiments; about 48 GB free on this machine)                                                                 | Every Rust build, spikes R2 to R4, parallel agents | High            | The resource watch in [README.md](README.md#resource-watch): one shared `CARGO_TARGET_DIR`, at most 2 Rust-building agents, stop below 20 GB free or 4 GB available memory, remove worktrees after push                       |
| **Debugging across the boundary**                                                                                                                           | M6                                                 | Medium          | `console_error_panic_hook` in debug builds, source maps, the corpus naming the failing layer                                                                                                                                  |
| **Clean room**                                                                                                                                              | Scales, chords, signals, anything "Strudel-style"  | Low             | Only this repository's TypeScript and public documentation pages are read; never Strudel or Tidal source; no `@strudel` packages (as `docs/coming-from-strudel.md` and #44's clean-room note already practise)                |
| **Documentation drifts behind the code** (guide gaps, API tables, the Rust guide)                                                                           | Every milestone                                    | Medium          | Documentation steps are explicit in every milestone; the M1 guide audit lists today's gaps; `docSnippets.test.ts` runs standalone blocks; `bun run docs:build` runs whenever docs or the theme change                         |
