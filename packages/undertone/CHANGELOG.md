# Changelog

## 0.4.0 (unreleased)

### Moving from 0.3

The package is rebuilt over a Rust core compiled to WebAssembly (the Rust migration, `docs/rust-migration/`). The JavaScript names and behaviour are 0.3's. These are the changes, the ten accepted as D-06 (decision D-40) and the ones the first bindings add.

#### Accepted breaks (D-40)

- **B1. Loading.** The package instantiates a WebAssembly module, so the default entry uses top-level `await` (Node, Bun, and Deno load it synchronously through the `node` condition). Where top-level `await` is not available, import `@liminal-hq/undertone/init` and `await init()` once; **with `./init`, `CHANNEL_ORDER`, `MAX_CHANNELS`, `SHAPED_WAVE_TYPES`, and `fmPresets` are `undefined` until `init()` has finished.** Vite 5 needs `build.target: 'esnext'`; see the README and the guide's _Runtimes and loading_ page. Rendering lives in a second module that loads on first use (below).
- **B2. Runtimes.** Node 22 or later, Bun 1.2 or later (D-42), and browsers with WebAssembly, top-level `await`, and `FinalizationRegistry`; 0.3's Node 20 floor is gone.
- **B3. Time beyond 2^53.** `Fraction` arithmetic is exact beyond 2^53 (as the Rust core's 128-bit fractions are) where 0.3 silently lost precision. `n` and `d` are then the nearest numbers, and `toString()` is exact. `Fraction.fromText('n/d')` is new.
- **B4. JavaScript queries.** `new Pattern(query, sample)` still works, as a foreign leaf, but a pattern that holds one runs only on the thread that made it: the AudioWorklet backend refuses it with a diagnostic naming the leaf.
- **B5. JavaScript functions in patterns.** `fmap(fn)` and `signal(fn)` follow B4. `fmap` calls `fn` once per value, and the batch crosses to WebAssembly once per query.
- **B6. Rendering.** `renderToBuffer` and `.render` render in the WebAssembly engine instead of an `OfflineAudioContext`, so the samples equal the browser's only within the render tolerances; passing `context` keeps the browser path. So with no `context` and no `OfflineAudioContext` (Node, say), `renderToBuffer` renders where 0.3 rejected, asking for a `context` factory.
- **B7. Internals.** Members of `Pattern` beyond `.query`, `.sample`, and the documented methods (the private fields and helpers) are not present.
- **B8. Size.** The package is larger. After Brotli: the main module is 147.8 KB (inside D-07's 150 KB budget) and its glue 14.4 KB; the render module, loaded only by a render, is 97.1 KB and its glue 5.5 KB; the wrapper's JavaScript is 25.7 KB. The packed tarball is 428 KB.
- **B9. Object identity.** Every query returns new `Hap` and `Fraction` objects. Within one query, haps with equal values share one value object (as the haps of one mini-notation word did).
- **B10. Errors.** Error messages are word for word the reference's, and the class is still `Error`.
- **B11. Booking order of stacked voices** (accepted in M6, after D-40). `play()` and `loop()` book a window's voices in onset order (the Rust scheduler's rule, so a window books the same however the loop splits time), where 0.3 booked a stack layer by layer, in the order the pattern listed them: `layer(note('a4 a4'), [{}, {}])` books layer 1's first note before layer 0's second. Start times and the sound are unchanged; only the order of the nodes on the context differs.

#### New with the bindings

- **A pattern's value cannot be `null` or a class instance.** `pure(null)`, `choose(new Fraction(1, 2))`, or a mini-notation leaf function returning one throws `a pattern value must be a number, a string, a boolean, undefined, an array, or a plain object, got ...`. Numbers (`NaN`, `Infinity`, `-0` included), strings, booleans, `undefined`, arrays, and plain objects (to 64 levels) cross unchanged. Use `undefined` or a plain object where you used `null`.
- **An array given to the module may be at most 4,194,304 items wide.** A wider one (`pure(new Array(0xffffffff))`, a sparse array whose length alone is huge) throws `... may be at most 4194304 items wide, got 4294967295` instead of trying to reserve room for its length and stopping the instance. It applies to pattern values, `choose`, `layer`, `foldToStereo`, `pitchsteps`, `channels`, `panpath`, `score` events, and the arrays of a sample or a play call, including the lists of the `./wasm` module's `registerSamples` and of the render module's exports.
- **A failed `init()` can be called again.** With `./init`, a load that fails (a dropped fetch) rejects its callers and is not kept: the next `init()` tries again, as the render module's loader already did.
- **Map keys come back sorted.** A value that is an object has its keys in alphabetical order, where 0.3 kept insertion order.
- **Equal values within one query share one object.** Mutating a value you got from one hap can show in another hap of the same query that holds an equal value; copy before you change one.
- **`free()` and `using`.** `Pattern#free()` and `[Symbol.dispose]()` are new, optional, and safe to call twice; see the README.
- **Overflow.** A pattern whose times overflow 128-bit fractions (`pure(1).fast(2 ** 53).fast(2 ** 53).fast(2 ** 53)`, queried) stops the WebAssembly instance (`RuntimeError: unreachable`) where 0.3 silently lost precision; reload the page or the process.
- **`@liminal-hq/undertone/testing`** is new (D-28): `resetWarnings`, `seedContext`, `playVoice(ctx, params, startTime, options?)`, and `playVoices(ctx, voices, when, options?)` (0.3's internal signatures), kept out of the API report. `resetWarnings` clears the main module's, the render module's, and the wrapper's once-only warnings.
- **`fmPresets` keys are in alphabetical order** (`glassBell`, `lead`, `pluck`, `roundBass`, `softPad`), where 0.3 listed them in the order they were written. The presets are frozen, as before.
- **Constants and presets are read from the module.** `CHANNEL_ORDER`, `MAX_CHANNELS`, `SHAPED_WAVE_TYPES`, and `fmPresets` are live bindings set when an entry loads the module; with `./init` they are `undefined` before `await init()`.
- **Odd inputs the reference accepted by accident are refused or read differently.** A patternable control given `undefined` or `null` throws `gain() needs a number, a mini-notation string, or a pattern, got undefined` (0.3 threw a `TypeError` from inside its parser); a numeric string as the rate of `pitchsteps()` or `panpath()` is refused (0.3 stored the string); a string `push` in `drift()` is read as a number (0.3 added it to the nudge as text); a field of `fmVoice()` that is not a number is refused (0.3 copied it); a number field of `score()` that is not a number reports `NaN` where 0.3 printed the value as given; and `true` or an object given to a patternable control is read as `String(value)`.
- **Warnings are printed by the modules** with `console.warn`, once per key per instance of a module; the few fallbacks the wrapper applies itself (a context without an optional factory) warn once each too.

#### New with the engine (playing, rendering, samples)

- **Two modules.** Rendering is in a second WebAssembly module that loads the first time it is needed (a dynamic `import()` in a browser; a synchronous read from disk under Node, Bun, and Deno), so a program that only plays never loads it. `encodeWav()` is TypeScript (0.3's encoder, byte for byte), so it works on every runtime before any render too (it needs only the main module, for its seeded dither).
- **A failed `play()` or first `loop()` window leaves nothing sounding** (D-38): the voices it booked before the failure are cut at once with a 5 ms fade, and the call throws. 0.3 left them playing. The same holds when the context itself throws in the middle of a booking (a `createOscillator` that fails, say): the sources the call made are stopped and disconnected, so nothing it booked is left sounding or scheduled, and the first error is thrown. Later ticks of a running loop that hit such a failure still book the rest of their window and throw the first error, and the earlier windows keep playing. `playParams` still leaves the voices before a failing one booked, as 0.3 did.
- **Samples:** the decoded PCM of a sample goes into one registry per module instance, not one per context, so once a sample has been decoded on any context every context plays it (0.3 skipped it on a context that had not decoded it yet). A `url` or `data` sample is decoded on a context when a voice first names it there, or by `loadSamples(ctx)`, as in 0.3. A voice plays the `AudioBuffer` you registered or that was decoded on its context, as before.
- **Registering a sample again takes effect.** What a context decoded for a name belongs to that registration: registering the name again (also while its decode is in flight) or clearing the registry retires it, and the next `loadSamples` or voice decodes the new source. A buffer decoded on a second context is matched to the module's PCM by what it holds (frames, channels, sample rate), so a decode that was resampled to that context's rate is not played in place of the PCM the module holds.
- **Noise and reverb are seeded with 0 on a context nobody seeded**, so they repeat from run to run; 0.3 used `Math.random` there. `seedContext` (`./testing`) and a render's `seed` work as before.
- **`buildImpulseResponse(ctx, seconds, random)`** fills its buffer in JavaScript, as 0.3 did, since `random` is a JavaScript function; with `seededRandom(seed)` it gives the module's own numbers.
- **`encodeWav`** refuses a `bitDepth` other than 16, 24, or 32 (`encodeWav: bitDepth must be 16, 24 or 32, got 8`); 0.3's types allowed only those, and its JavaScript wrote a broken header.
- **A render is bounded** at 2^28 samples in all channels (D-37); a longer one rejects with an error where 0.3 tried to allocate it.
- **Some of the reference's own tests are not run here:** the 25 internal tests of the ported files test private functions (Rust unit tests cover them), and one public test, the layer velocity order, expects B11's onset order. Every other public and Web Audio test of the reference's engine, scheduler, render, WAV, and sample suites passes against the package, and the whole corpus (layers 1 to 4 and WAV) runs through it.
