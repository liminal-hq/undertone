Undertone head to head

Is the Rust and WebAssembly engine faster than the TypeScript reference engine at the same work, on this device and browser? Each song is rendered offline by both engines (one discarded warm-up render, then three timed renders, alternating TypeScript and WebAssembly so thermal drift shows), and the table gives the milliseconds of each run, the median, the speed as a multiple of real time (audio seconds over wall seconds) and the ratio of the WebAssembly median to the TypeScript one (below 1 means WebAssembly is faster). Peak and RMS are shown so you can see that the two engines made the same audio.

What is and is not comparable: the TypeScript engine builds Web Audio nodes (oscillators, filters, a ConvolverNode) and the browser renders them in its own native code; the WebAssembly engine does its own DSP in a WebAssembly module on the page. The offline numbers compare the two as renderers of the same song, which is fair, but they do not compare how the work is done: the native reverb, for instance, may use a different algorithm and a different cost. The peaks agree to about a thousandth where Web Audio allows, and the audio is not identical sample for sample.

The real-time mode plays each song for a while with each engine and records how the page's main thread behaves: the jitter of a 1 ms timer (browsers clamp it, so read it as relative) and the long tasks (over 50 ms) where the browser reports them. The TypeScript engine's audio work runs inside the browser's audio engine, where this page cannot time it, so that mode shows only how much the engine disturbs the main thread; the WebAssembly engine's audio work runs in the audio worklet, also off the main thread. Sound plays in that mode.
